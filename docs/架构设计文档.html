1. iCloud 网页端机制 · 实测逆向结论

以下结论来自 2026-09-08 对 icloud.com.cn/photos 的实际操作（滚动 / 缩放 / 详情 / 实况 / 视频）、网络请求抓包与前端 JS bundle 源码分析（photos3 应用，2632Build19）。

1.1 照片墙网格：自研虚拟滚动 + 衍生图分级

机制实测证据对应设计启示
虚拟滚动滚动容器 grid-scroll 的 scrollHeight 达 240,255px（放大后 1,578,463px），但 DOM 中 grid-item 始终只有 ~168 个（视口内仅可见 24~36 个）。滚动跳转后立即读 DOM：items 不变、img 清空，随后按新位置重建。无 IntersectionObserver，滚动容器用自研窗口算法计算可见范围。只渲染「视口 + overscan」，不渲染全部 1.2 万项
定位方式grid-item 为 position:absolute + transform: translate(x,y)（实测 matrix 值），宽高像素级设置，父容器 grid-items 为 relative。绝对定位 + transform 平移，避免回流
列数 / 缩放滑块拖动实测：8列120px → 5列201px → 3列346px；源码常量 columnCountMin:3, columnCountMax:9, columnCountDefault:5。网格总高随列数变化（240K→585K→1,578K px）。关键：缩放全程未触发新的图片请求——同一张衍生图复用。缩放只改 CSS 布局与列数，不重载图片
缩略图加载缩略图类名 DerivativeImage，实际显示 120~346px，但 naturalWidth ≈ 415px。加载方式为 XHR → blob → URL.createObjectURL → img.src，请求打到 cvws.icloud-content.com.cn/B/<assetID>/public.jpeg?o=<签名>&v=1&x=3&a=<鉴权>（签名带过期时间）。滚动到新区域触发 ~59 个并发 XHR。单档 ~400px 缩略图覆盖全部网格缩放范围；本地可简化用 img 直连 + 磁盘缓存
请求优先级源码 offscreeniness（离屏程度）字段参与请求调度；erroredSlots 记录失败槽位并降级重试；isSizeLargeEnough(derivativeMSL, desiredSize) 选择"≥目标尺寸的最小档位"。图片加载器带优先级队列 + 失败降级
日期分组GridHeader 顶部显示当前日期；网格按拍摄时间排序连续排列；源码有独立的 SectionHeaders 类（renderSectionHeaders / arrangeSectionHeaderDOMElements）。日期作为排序键 + 独立头部层

1.2 详情页：OneUp 轮播 + 激进预加载

机制实测证据对应设计启示
轮播结构详情视图类名 OneUp / OneUpCarousel（基于 ReactSwipeCarousel），DOM 常驻 3 个 OneUpCarouselItem（前/中/后）。URL 变为 hash 路由 #/i,pz,<assetGUID>,<index>/，可前进后退、可分享定位。三格轮播 + hash 路由记录位置
大图加载详情图 naturalWidth=2048（网格 415px 的 5 倍），同样是 blob 注入；ProgressiveImageElement 带 opacity 0.3s 过渡淡入。方向键切换后，3 个 item 全部在切换完成前就已具备 2048px 大图——邻居预加载。详情档 ~2000px；预加载前后各 1~2 张
实况照片结构：静止帧 img（blob 大图）+ LivePhotosPresenter 内叠一个 <video>（同源 mp4，position:absolute; z-index:1; opacity:0; transition:opacity 500ms）+ 顶部「实况」徽标（pointer capture 区域）。实测：按住 → video opacity 变 1 并 play()（currentTime 0→2.2s）；松开 → pause() + opacity 归 0 + currentTime 归零。img + 隐藏 video 叠层，按住播放、松开重置
视频原生 <video>（videoplayer.js 为 Video.js 封装），preload="metadata"，mp4 直接流式。用 fetch 探测视频 URL 的 Range 请求：返回 HTTP 206、content-length 1024，确认基于 Range 分段流式（非 HLS 分片）。原生 video + HTTP Range 流式即可
实况/邻居预取切换轮播时抓包看到相邻项的 public.mp4 视频请求（含实况视频）被提前拉取；源码枚举了 GridAsset / GridAssetPrefetch / OneUpMainDisplay / OneUpMainDisplayPrefetch / OneUpVidComplPrefetch / OneUpNonHlsVideoPlaybackBegin 等预取分级。预取分级：按场景（网格/详情/实况）定义资源档位与时机

1.3 数据与传输层

  • 元数据：CloudKit 接口 ckdatabasews.icloud.com.cn/.../records/query 分页拉取（单次响应 24~55KB，数百条），另有 changes/zone 增量同步。→ 本地用 SQLite 单表即可，一次扫描全量入库。
  • 签名 URL：资源 URL 带 o/e/a/s 等签名参数与过期时间（实测 e=1788800643 即当前时刻），服务端鉴权后放行。→ 本地无鉴权需求，静态服务 + ETag 即可。
  • 逆地理编码：geows reverseGeocodeCoordinates 批量把 GPS 转为地名。→ 可选功能，本地可用离线库或省略。
  • HEIC 处理：iCloud 服务端把 HEIC 转码为 JPEG/WebP 衍生图（源码 isTranscoded / isTranscoderRequest 字段）。→ 本地用 sharp（libvips + libheif）做同样的转码，逻辑等价。

2. 总体架构

前后端分离的单机应用：Node.js 后端负责目录扫描、元数据入库、缩略图/视频流水线、静态资源服务；Vue 3 前端负责虚拟滚动网格、详情轮播、实况照片与视频播放。后端只读本地磁盘，不依赖任何外部服务，浏览器访问 http://localhost:8899 即可。

前端（Vue 3 + Vite）网格虚拟滚动 · 图片加载器 · OneUp 轮播 · 实况照片 · 视频播放 · Pinia 状态
⇄ HTTP / JSON
API 层（Fastify）资产查询 · 缩略图 · 视频流 · 扫描任务
⇄
服务层目录扫描与配对 · 元数据提取 · 缩略图流水线 · 视频转码 · 任务队列
⇄
数据层SQLite（better-sqlite3）· 缩略图磁盘缓存 · 原文件只读
核心设计原则：把「计算」提前到入库阶段（一次扫描生成元数据 + 按需生成缩略图），把「渲染」放到前端虚拟化（永远只渲染视口附近的几十个节点），把「带宽」降到零（本地磁盘读取，Range 流式）。

3. 后端设计（Node.js）

3.1 技术选型

职责选型理由
运行时Node.js 20+ LTS + TypeScript用户指定 Node；TS 保证 12k 资产模型的类型安全
Web 框架Fastify 5性能好、内置 JSON Schema 校验、插件生态完善；如更熟 Express 也可（Express 的 res.sendFile 同样原生支持 Range）
元数据数据库better-sqlite3同步 API 快、单文件零运维；1.2 万行完全够用；SQLite FTS5 可做搜索
EXIF 提取exifr解析 HEIC/JPEG 的拍摄时间、GPS、方向、尺寸，支持分段读取大文件
图像处理sharp（libvips）生成 WebP 缩略图 4~5 倍于 ImageMagick。注意（实测坑）：sharp 官方预编译不含 HEVC 解码插件（HEIC 的 metadata 可读、转码报 heif: No decoding plugin installed (11.6003)），需配合 ffmpeg full 版解码，见 §9
视频抽帧 / 转码BtbN ffmpeg full 版 + fluent-ffmpeg抽取视频封面帧；同时承担 HEIC 解码（full 构建含 libheif，实测 0.13s/张）。npm 的 ffmpeg-static 是精简版（无 heif demuxer），需用 scripts\install-ffmpeg-full.ps1 替换
任务队列p-queue（进程内并发控制）缩略图生成 / 转码任务加并发上限（如 4），避免 IO 打满；单机无需 Redis
静态服务@fastify/static自动支持 Range / ETag / Last-Modified，视频拖动进度条依赖 Range

3.2 目录扫描与实况配对（关键）

iCloudPD 默认输出结构：YYYY/MM/DD/<文件名>，实况照片拆成两个文件，命名策略（默认 suffix 模式）如下：

原图类型静止帧文件实况视频文件
HEICIMG_1234.HEICIMG_1234_HEVC.MOV
JPEGIMG_1234.JPGIMG_1234.MOV
配对规则：扫描时对每个文件计算「去后缀 + 去 _HEVC 后缀」后的基名，基名相同且一个为图片（HEIC/JPG/PNG…）一个为视频（MOV/MP4…）即配对为实况照片（iCloudPD 的 suffix 命名天然保证一一对应，无时间差校验）。视频不带静态帧配对的即为普通视频。

3.3 入库流水线

① 扫描遍历目录树，按扩展名分类图片/视频
→
② 配对基名匹配 + 时间校验，标记 live
→
③ 读元数据exifr 提取时间/GPS/方向/尺寸；视频用 ffprobe 读时长
→
④ 入库UPSERT 进 SQLite，记录文件路径与 checksum
→
⑤ 入队生成缩略图 / 抽视频帧 / 按需转码

增量设计：以 file_path 为唯一键 UPSERT；checksum 变化视为新文件。首次全量扫描 1.2 万文件约几分钟（纯文件系统 IO），可后台运行并实时汇报进度。

3.4 缩略图流水线

参照 iCloud 的「档位 + 按需」模型，定义两档 + 一占位：

档位规格用途全量估算
grid最长边 320px，WebP q80网格任意缩放级别复用（实测 iCloud 415px 档覆盖 120~346px）~25KB/张 × 12,457 ≈ 0.3GB
detail最长边 1600px，WebP q82详情页大图（对标 iCloud 2048 档，本地 1600 已足够）~250KB/张 ≈ 3GB（可仅按需生成最近浏览的）
blur20px 高斯模糊（或 thumbhash）滚动时的即时占位~1KB/张，可忽略
video posterffmpeg 抽第 1 秒帧 → 320px WebP视频缩略图~60KB × 3,034 ≈ 0.18GB

生成策略：懒生成 + 优先队列。前端请求某张缩略图 → 后端查缓存未命中 → 生成并入磁盘缓存（ETag 缓存到浏览器）；首屏可视区请求的优先级最高。后台队列（p-queue 并发 8）持续预热，浏览到的区域现场生成（实测冷生成 grid 0.68s / blur 0.41s，热缓存 25ms）。同一资产并发请求用 in-flight Map 去重（只生成一次，防止并发写坏文件）。

3.5 视频播放与转码（关键风险点）

实测更新：本机 Chrome 可直接播放 HEVC/H.265 的 MOV（策略 A 原片直出 + Range 206 已验证，进度条拖动、时长、实况视频播放均正常）。若目标机器缺失系统 HEVC 扩展导致黑屏，再启用策略 B 转码兜底。
策略做法评价
A. 原片直出（推荐起步）/api/video/:id/stream 直接流式原 MOV + Range。前端 <video> 播放，若 error 事件（编码不支持）则提示装 HEVC 扩展或切转码版零转码成本，先跑通
B. 按需转码缓存（推荐最终态）播放时检测编码：非 H.264 则后台任务用 ffmpeg 转 H.264（-c:v libx264 -preset veryfast -crf 23），产物存 cache/transcoded/，前端回退到 /api/video/:id/stream?variant=h264首次播放需等转码（可转 360p 预览先行）；有硬件编码（qsv/nvenc）可加速
C. 全量预转码入库后后台批量转全部 3,034 个视频150GB 原片转码耗时数小时~天级，资源消耗大；不推荐首版

实况照片视频同样走此通道（HEVC 兼容问题一致）；由于实况视频通常仅 2~5 秒，按需转码极快，体验无损。

3.7 数据库 Schema（SQLite）

CREATE TABLE assets (
  id            INTEGER PRIMARY KEY,
  file_path     TEXT UNIQUE NOT NULL,        -- 相对库根目录的路径

4.2 网格虚拟滚动（对标 iCloud 核心）

① 布局计算容器宽 ÷ 列数（3~9）→ item 尺寸；总高度 = Σ行高 + 日期头高度
→
② 滚动监听scrollTop → 可见行区间 [start, end] + overscan 2~3 行
→
③ 增量渲染进入窗口的项挂载 GridItem（absolute + transform），离开的卸载
→
④ 图片预取对可见项 + 前后 2 屏发起 thumb 请求，按优先级入队
→
⑤ 缩放滑块改列数 → 重算布局与总高 → 复用已缓存缩略图（不重载）

关键参数：overscan 行数 2~3（对标 iCloud 的 ~168 节点 ≈ 视口的 4~5 倍）；滚动节流用 rAF 合并，避免每帧重算。

@tanstack/vue-virtual 两个必踩的坑（P0 实测定位）：① useVirtualizer 返回的是 ref（shallowRef 包装），script 里必须 rowVirtualizer.value.xxx()，模板会自动解包；② count 选项必须写成对象 getter（get count() { return totalRows.value }）——直接传 ref 或函数，core 会用「数值 vs 对象」比较，虚拟项恒为空（virt=0），且元素挂载晚于初始化时需手动 measure()。

日期分组定位（P1 已落地，2026-09-08）——把「按日期浏览」还原为三层：

  • 行模型混合：虚拟滚动的行数组 =「月份头行 + 资产行」混合（月份变化时插一行头，estimateSize 按行类型返回 34px / 资产行高），滚动条长度依然精确；
  • 吸顶月份指示器：滚动容器外固定一条，取第一个可视行的月份实时更新（对标 iCloud GridHeader）；
  • 日期导航面板（方案 C，复刻 iCloud 截图布局）：工具栏「日期」按钮 → 下拉面板（左侧年份列表 + 右侧月份缩略图网格 3 行×4 列，无滚动条；/api/dates 一次拉全约 108 个月，含每月 offset 与代表缩略图 thumbId）。点月份 → /api/assets?offset=N 跳页加载（后端保证该页以目标月首资产开头）→ 滚动归零即直达月份头，之后游标无缝接续向下滚动。面板 toggle 开/关，点击外部/Esc 关闭。

已实现但暂未覆盖：向上翻页（跳转后向更早月份继续滚动只能靠再次点定位条）——留待 P2 补「加载上一页」。内存 LRU 因本地场景收益低已后置。

4.3 图片加载器（对标 DerivativeImage）

  • 两级缓存：内存 LRU（上限 ~300MB，存最近浏览的 blob）+ 浏览器 HTTP 缓存（后端 ETag）。
  • 占位策略：未加载完成显示 blur 占位（blur 档或 CSS 模糊），加载完成后 opacity 过渡淡入（复刻 ProgressiveImageElement 的 0.3s）。
  • 优先级：视口内 > 预取窗口 > 后台预热；并发上限 8~12（本地 IO 快，可调大）。
  • 错误降级：失败自动重试 1 次后显示占位图标，并在后台任务列表重排生成。

4.4 详情页（OneUp 轮播）

  • DOM 常驻 3 个 OneUpItem（前/中/后），切换用 CSS transform 滑动 + 位置索引滚动；方向键 / 触摸 / 点击左右区域切换。
  • 预加载邻居：进入详情即请求「当前 ± 2」的 detail 档缩略图；若邻居为实况照片或视频，同时预取其实况视频头（metadata 级）。
  • hash 路由同步：#/i,pz,<assetId>,<index>/，支持浏览器后退直接回到网格对应位置。
  • 渐进显示：先 blur 占位 → grid 档秒出 → detail 档淡入替换（三步渐进，对标 iCloud 体验）。

4.7 主题切换与详情返回位置保留（2026-09-08 审查后落地）

  • 主题系统：浅色/深色双主题 = 根元素 [data-theme] + CSS 变量（--bg-*/--text-*/--border/--accent），所有组件引用 var()，切换零重渲染。默认浅色。持久化 localStorage（key icloud-app-theme），index.html 内联脚本在 CSS 生效前设初值防闪烁。详情页/实况/视频查看区恒深（对标 iCloud 白天主题下详情查看器仍为黑底白字）。主题化范围：App/GridView/GridScroller/DateNavPanel。
  • KeepAlive 缓存照片墙：<KeepAlive :include="['GridView']"> 包路由出口，返回详情时滚动位置/已加载数据/搜索态原样保留（详情页不缓存，大图 DOM 不常驻）。
    • 滚动位置保存/恢复：deactivated 钩子与路由切换瞬间都读不到真值（DOM 已移出文档），改为 onScroll 持续记录 + onActivated 写回 + 派发 scroll 事件重算可视窗口。
    • 行高错位坑：缓存期间 ResizeObserver 把 clientWidth 读成 0 → viewportWidth 污染 → 恢复瞬间用兜底行高测量 → 行重叠/间距异常（实测宽窗口重叠、窄窗口间距变大，同源）。修复：RO 忽略宽度 0 + 恢复时 rAF 内先 measure 再派发 scroll。
  • ⚠ 缓存失效机制（P2+-1 前置注意）：KeepAlive 缓存的照片墙在同步/热监听/删除同步落地后不会自动感知后端数据变化——P2+-1 必须实现「同步完成 → 前端通知照片墙失效缓存并刷新」（如 store 暴露 reload 标志 + GridView onActivated 时检查，或同步后强制整页刷新路由）。当前本地静态库无影响。

9. 踩坑记录（P0 实测，学习价值高）

坑现象根因与修复
HEIC 解码失败缩略图 500，生成 0 字节文件；日志 heif: No decoding plugin installed (11.6003)sharp 官方预编译不含 HEVC-HEIC 插件（metadata 可读、转换失败）。修复：BtbN ffmpeg full 版（含 libheif）解码为 JPEG 再交 sharp；scripts\install-ffmpeg-full.ps1 + postinstall 固化，重装依赖自动恢复。实测 0.13s/张（WASM heic-convert 1.5s/张作兜底）
virtual 虚拟项恒空（virt=0）网格 items 有数据但一行都不渲染useVirtualizer 返回 ref；count 必须用对象 getter get count(){...}（传 ref/函数时 core 数值比较恒 false）。元素晚挂载需手动 measure()。查了库源码 getMeasurementOptions 才定位
flex item 百分比高度塌陷详情页图片/视频区域 0 高度（父 flex:1 有高度，子 height:100% 解析为 0）flex item 的百分比高度在多数浏览器不解析。修复：舞台元素统一 position:absolute; inset:0（父为 relative）
better-sqlite3 参数爆炸RangeError: Too many parameter values were providedEXIF 的 GPS 度分秒返回数组 [50,30,10]，驱动把数组当参数列表展开。修复：dmsToDecimal() 先换算成十进制度数
exifr Orientation 返回字符串API 返回 "Rotate 90 CW" 而非数字 1~8exifr 默认翻译值。修复：parse(..., { translateValues: false })
实况照片按住不播放按住只有淡入效果，视频不动只设了 playing=true（opacity），从未调用 video.play()。修复：nextTick 后 play()，松开 pause() + currentTime=0；setPointerCapture 包 try/catch 兼容合成事件
Windows npm 安装二进制下载失败better-sqlite3 / ffmpeg-static postinstall 从 GitHub 下载超时GitHub 主站不通时用 npmmirror 二进制镜像：npm_config_better_sqlite3_binary_host=...、FFMPEG_BINARIES_URL=...（不带版本号）
KeepAlive 下滚动位置读不到详情返回后照片墙总是回到顶部deactivated 钩子触发时 DOM 已移出文档（scrollTop 归零），路由切换瞬间亦然。修复：onScroll 持续记录位置，onActivated 写回 + 派发 scroll 事件
KeepAlive 返回后行高错位宽窗口行重叠 / 窄窗口间距变大（同源）缓存期间 ResizeObserver 把 clientWidth 读成 0 污染 viewportWidth → 恢复用兜底行高测量。修复：RO 忽略宽度 0 + 恢复时 rAF 先 measure 再派发 scroll
